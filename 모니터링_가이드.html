한눈에 보기

무엇을 하나

드림몰·교직원공제회(thek)의 PC/모바일 화면을 실제 브라우저(Chromium)로 열어 9개 시나리오를 점검하고, 결과를 두레이 메신저로 알립니다.

어디서 도나

GitHub Actions UI_Test scheduler가 6시간 간격 cron으로 실행합니다. 수동 실행도 가능합니다. 이 PC의 Windows 작업 스케줄러에는 등록된 작업이 없습니다(로컬 실행은 수동).

인수 시 꼭 바꿀 것

새 레포에는 코드만 올라가고 .env와 Secrets는 따라가지 않습니다. 같은 값을 GitHub Secrets(자동 실행용)와 로컬 .env(로컬 테스트용) 두 곳에 저장해야 합니다. 상세는 Secrets ↔ .env를 보세요.

①인수 시 바꿔야 하는 정보 (체크리스트)

체크박스는 화면 확인용입니다(저장되지 않음). 필수는 안 바꾸면 동작/알림이 끊기거나 이전 담당자 정보가 남는 항목입니다.

필수

Secrets와 .env에는 같은 값이 들어가야 합니다. 저장하는 곳만 두 곳입니다. 둘은 서로 연결돼 있지 않아서, 값이 바뀌면(계정 비밀번호 변경 등) 양쪽 모두 고쳐야 합니다.

.env 값은 이미 설정된 시스템 환경변수보다 우선합니다(load_dotenv(override=True)). .env는 git에 없으니 담당자마다 직접 만들어야 합니다.

필수

같은 ID/PASSWORD 한 쌍으로 로그인이 필요한 모든 몰(드림몰, thek)에 로그인합니다. 따라서 두 몰 모두에 가입돼 있고 로그인 가능한 test 계정 사용을 권장합니다.

계정을 교체하면: ① GitHub Secrets ID/PASSWORD 갱신 ② 로컬 .env 갱신 ③ 각 몰에서 로그인과 장바구니 담기가 되는지 python main.py --show로 확인.

필수
  • 알림을 받을 두레이 채널에서 Incoming Webhook URL을 새로 발급해 Secret WEBHOOK_URL에 등록합니다.
  • 봇 표시 이름은 config.yaml의 dooray.bot_name(현재 “드림몰 테스트봇”)입니다.
  • 성공해도 매 실행마다 발송됩니다(“ERROR 건수 : 0건”). 실패가 있으면 [몰 PC/Mobile] 항목 - 오류 목록이 함께 갑니다.
참고
  • 코드에는 아이디·전화번호·주소 같은 개인정보가 없습니다(배송지 폼에는 “테스트”만 입력). 계정 정보는 환경변수(ID/PASSWORD)로만 읽습니다. 코드는 고칠 필요 없이 Secrets와 .env만 새로 설정하면 됩니다.
  • .env 파일은 한 번도 커밋된 적이 없고, 두레이 웹훅 URL이나 비밀번호가 코드·히스토리에 하드코딩돼 있지 않습니다(과거 예시 설정 파일에 YOUR_PASSWORD 자리표시자만 있었음).
  • 다만 과거 커밋에 스크린샷·영상 22개가 올라가 있습니다. 로그인된 화면이 찍혔다면 계정명 등이 보일 수 있으니, 히스토리째 옮길지 현재 상태만 옮길지 정할 때 참고하세요.
확인

최근 30회 실행 기준 1회 평균 약 15분(최대 32분)입니다. 지금처럼 하루 약 3회면 월 약 1,300분, 설정대로 6시간마다(하루 4회)면 월 약 1,800분입니다. 공개 레포는 무료이지만 비공개 레포는 플랜별 월 무료 사용 시간에 걸립니다(GitHub 무료 플랜은 월 2,000분 안팎). 옮길 곳의 플랜과 정책을 확인하세요.

③사용 방법

3-1. 로컬 실행

Python 3.11 이상이 필요합니다.

pip install -r requirements.txt
playwright install chromium

그다음 ①의 Secrets ↔ .env 표대로 파일을 만들고 실행합니다.

명령동작
python main.py전체 몰·전체 시나리오 (브라우저 숨김)
python main.py --show브라우저 창을 띄워서 실행 (디버깅용)
python main.py --mall dream특정 몰만. 몰 id나 이름 일부, 대소문자 무관 (dream, thek)
python main.py --only 검색,cart특정 시나리오만 (위 표의 별칭, 쉼표로 여러 개)
python main.py --mall thek --only gnb --show조합 사용 — 문제 재현할 때 가장 유용

순차 실행이 필요하면 환경변수 MAX_WORKERS=1을 줍니다. --mall=dream, --only=cart처럼 = 형태도 됩니다.

3-2. 결과물 위치

경로내용
reports/report_*.md마크다운 상세 리포트 (몰별 요약 + 항목별 결과 + 실패 상세)
screenshots/실패 시 자동 저장된 화면 (팝업 테스트는 성공 시에도 저장)

두 폴더 모두 git에서 제외되고, 실행할 때 7일 지난 파일은 자동 삭제됩니다.

3-3. GitHub Actions (자동 실행)

  • 워크플로 이름: UI_Test scheduler (.github/workflows/schedule.yml)
  • 수동 실행: 레포 Actions → UI_Test scheduler → Run workflow
  • cron은 7 */6 * * * (UTC). 즉 KST 기준 03:07 · 09:07 · 15:07 · 21:07입니다.
  • 실제로는 GitHub 스케줄이 부하에 따라 지연되거나 일부 건너뛰어, 최근 실행 기록을 보면 하루 약 3회이고 정시가 아닙니다. 이상이 아니니 놀라지 마세요.
  • 실행이 끝나면 test-reports(reports/), test-screenshots(screenshots/)가 아티팩트로 30일간 보관됩니다. 실패 화면은 여기서 내려받아 확인합니다.
Actions가 빨간 “failure”로 보이는 경우. 시나리오가 1건이라도 실패하면 프로그램이 종료 코드 1로 끝나서 Actions 실행도 failure가 됩니다. 인프라 장애가 아니라 “실패 항목이 있다”는 뜻입니다. 예: 2026-11-10 07:15 KST 실행은 35/36 통과, 실패 1건(thek Mobile)이었습니다. 어떤 항목인지는 두레이 메시지나 실행 로그의 ERROR 내역에서 확인하세요.

④수정 방법

4-1. 점검 대상 몰 추가 / 제외 — config.yaml

malls:
  - name: "새몰(example)"
    id: example
    urls:
      pc: "https://example.onuri.co.kr/"
      mobile: "https://mexample.onuri.co.kr/"
    requires_login: true
    # login_url: "https://.../indexLogin"   # 로그인 주소가 기본 규칙과 다를 때
    # search_valid: [수건, 텀블러]            # 이 몰 전용 검색어 (없으면 search.valid 사용)
    # categories: [식품, 뷰티]               # 이 몰 전용 카테고리 (없으면 categories.pool 사용)
    # skip: true                             # 삭제하지 않고 점검만 잠시 제외
  • 제외: 항목을 삭제하거나 skip: true를 추가합니다. 최근 poba(행정공제회)와 삼아(samaint)는 항목을 삭제해서 뺐습니다. 다시 넣을 수도 있으니 앞으로는 skip: true가 편합니다.
  • 추가: 새 몰은 같은 ID/PASSWORD로 로그인하므로 그 몰에 같은 계정이 있어야 합니다.
  • 로그인 주소를 따로 안 주면 메인 URL의 /main을 /indexLogin으로 바꿔서 시도합니다(tests/base.py의 login).

4-2. 검색어 · 카테고리 · 봇 이름 — config.yaml

search:
  valid: [생수, 수건, 물, ...]     # 검색 테스트용 키워드 풀 (매 실행 무작위 선택)
categories:
  pool: [가전/디지털, 식품, ...]   # 카테고리 테스트 풀
  count: 5                         # 풀에서 무작위로 뽑는 개수
dooray:
  bot_name: "드림몰 테스트봇"      # 두레이에 표시되는 봇 이름

카테고리 이름은 사이트 GNB의 실제 표기와 같아야 합니다. 사이트가 카테고리명을 바꾸면 여기도 같이 바꿔야 실패하지 않습니다.

4-3. 실행 주기 — .github/workflows/schedule.yml

cron은 UTC입니다. 한국 시간에서 9시간을 빼서 적습니다.

원하는 시각 (KST)cron (UTC)
매일 09:000 0 * * *
매일 09:00, 18:000 0,9 * * *
평일 09:000 0 * * 1-5
현재(6시간 간격)7 */6 * * *

정각(:00)은 GitHub 부하가 몰려 더 늦게 도는 경향이 있어 현재처럼 어긋난 분(:07)을 쓰고 있습니다. cron 줄을 수정·커밋하면 알림 대상 계정도 수정자로 바뀝니다(①-7 참고).

4-4. 시나리오 추가 / 변경

  1. tests/test_새이름.py를 만들고 run(page, url, ...) 함수를 작성합니다. 성공하면 비고 문자열을 return, 실패하면 예외(AssertionError 등)를 raise합니다.
  2. main.py 상단의 from tests import ...에 모듈을 추가합니다.
  3. run_platform() 안에 기존 블록(예: “9. 기획전 오류 확인”)을 복사해 run_test("이름", platform_label, page, lambda p: ...) 형태로 추가합니다.
  4. (선택) main() 안의 _TEST_ALIAS에 --only 별칭을 추가합니다.

run_test()가 예외를 잡아 실패 스크린샷 저장과 결과 객체 생성을 대신해 주므로, 시나리오 함수 안에서 따로 try/except 할 필요는 없습니다.

4-5. 사이트 UI가 바뀌어 테스트가 깨질 때

  • 먼저 재현합니다: python main.py --mall 몰 --only 시나리오 --show
  • 선택자(셀렉터)는 각 tests/test_*.py 상단 상수에 모여 있습니다. 팝업 닫기 버튼은 tests/base.py의 POPUP_CLOSE_SELECTORS, 로그인 입력칸은 같은 파일 login() 안의 후보 목록입니다.
  • 실패 화면은 screenshots/(Actions에서는 test-screenshots 아티팩트)에서 확인합니다.

4-6. 그 밖에

  • 의존성: requirements.txt (playwright, requests, pyyaml, python-dotenv). Actions의 Python은 3.11입니다.
  • 인코딩: 한글이 들어간 파일(config.yaml 등)은 반드시 UTF-8로 저장하세요.

⑤자주 겪는 문제

증상원인과 조치
두레이에 [로그인] ... 실패, 계속 진행 후 장바구니·배송지 등이 연달아 실패 테스트 계정의 비밀번호 변경·잠금·해당 몰 미가입이 흔한 원인입니다. 계정으로 직접 로그인해 보고, 바뀌었다면 Secrets ID/PASSWORD(와 .env)를 갱신합니다.
두레이 알림이 안 온다 웹훅 URL 만료·채널 삭제 여부 확인 → Secret WEBHOOK_URL 재등록. 로컬 실행이라면 .env 키가 DOORAY_WEBHOOK_URL인지 확인합니다(WEBHOOK_URL이면 읽히지 않음).
특정 몰의 Mobile만 가끔 실패 모바일은 UI 구조가 달라 타이밍·선택자 이슈가 생기기 쉽습니다. 일시적인지 확인하려면 --mall 몰 --show로 여러 번 돌려 보세요.
Actions가 안 돈다 Actions 탭에서 워크플로가 Disable 상태인지 확인(60일 무활동 자동 중지 또는 수동 비활성). Enable 하거나 cron 줄을 수정해 커밋하면 다시 시작됩니다. 레포를 옮긴 직후라면 ① Secrets가 등록됐는지 ② 기본 브랜치(main)에 워크플로 파일이 있는지 ③ 새 레포의 Actions가 켜져 있는지도 확인하세요. 스케줄은 기본 브랜치의 워크플로만 실행합니다.
실행 시각이 들쭉날쭉하다 GitHub 스케줄은 지연·누락이 있습니다. 설정(7 */6 * * *)과 실제가 달라도 정상 범위입니다.
로컬에서 브라우저를 못 찾는다 playwright install chromium을 실행하세요. 코드는 PLAYWRIGHT_BROWSERS_PATH 또는 %LOCALAPPDATA%\ms-playwright 아래의 chromium을 찾습니다.

⑥레포 구조

UI_test/
├── main.py                  # 진입점: 설정 로드, 몰/플랫폼별 실행, 리포트·두레이 발송
├── config.yaml              # 몰 목록, 검색어, 카테고리, 봇 이름
├── requirements.txt
├── .env                     # 계정·웹훅 (git 제외, 로컬 전용)
├── .github/workflows/
│   ├── schedule.yml         # Actions: UI_Test scheduler
│   └── admin_stat.yml       # Actions: 드림몰 Admin 통계
├── tests/
│   ├── base.py              # 브라우저 초기화, 로그인, 팝업 닫기, 스크린샷, run_test
│   └── test_*.py            # 시나리오 9개
├── report/
│   ├── generator.py         # 마크다운 리포트 / 두레이 요약 메시지

├── screenshots/ reports/    # 결과물 (git 제외, 7일 후 자동 삭제)
└── admin_stat/              # 드림몰 Admin 통계 전송 프로젝트 (admin_stat.yml 로 실행)
README.md는 일부 오래됐습니다. 이 가이드가 현재 코드 기준입니다. README에는 아래가 현재와 다르게 적혀 있습니다.
  • 환경변수 ACCOUNT_USERNAME → 실제는 ID/PASSWORD
  • Secrets username/password → 실제는 ID/PASSWORD
  • 실행 시각 08:38·14:38 → 실제는 6시간 간격 cron
  • 시나리오 8개 → 실제 9개 / 모바일 기기 Galaxy S5 → 실제 iPhone 14 Pro Max
  • config 예시가 단일 urls 구조 → 실제는 malls 목록 구조

admin_stat/는 Selenium 기반으로 드림몰 Admin 통계를 수집해 이메일로 전송하는 별도 프로젝트입니다. 루트의 main.py·report/와 이름이 같은 파일이 있어서, 워크플로(admin_stat.yml)가 항상 admin_stat/ 폴더 안에서 실행합니다. 로컬에서도 admin_stat/로 이동한 뒤 python main.py를 실행하세요.

인수 완료 전 최종 확인

  1. Secrets ID, PASSWORD, WEBHOOK_URL이 로컬 .env의 ID, PASSWORD, 두레이 웹훅 값과 같다.
  2. 새 담당자가 본인 PC에 .env를 직접 만들고(git에 없음), python main.py --mall dream --show가 로그인까지 성공한다.
  3. Admin 통계 Secrets가 admin_stat/.env와 같은 이름·값으로 등록돼 있다.
  4. 이전 담당자 PC의 .env를 삭제했다.
